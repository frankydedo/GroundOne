# Gou 2024 – CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing

**Raw file**: `raw/demo/Gou 2024 - CRITIC, LLMs Can Self-Correct with Tool-Interactive Critiquing (arXiv 2305.11738)_ingested.pdf`

## Overview
CRITIC is a **verify-then-correct** loop for black-box LLMs in which the verification step calls **external tools**: Google search for QA, a Python interpreter for math programs, the Perspective API for toxicity. The model writes a critique grounded in the tool output, then a corrected answer, and the cycle repeats until the output stops changing or an iteration cap is reached (Fig. 1, Algorithm 1). It is evaluated on free-form QA, mathematical program synthesis and toxicity reduction with text-davinci-003, ChatGPT and LLaMA-2 7B/13B/70B. The paper's main lesson is that **self-critique without the tools gives little or even negative gain**: external feedback is what drives the improvement (abstract, §1, §4).

## Key Insights
1. **Method (§3, Algorithm 1).** Initial output ŷ0 → critique c_i, generated by the LLM while interacting with tools → stop if the critique says the output is correct → otherwise correct, ŷ_{i+1} ~ P(· | x, ŷ_i, c_i). Everything is in-context (few-shot, ReAct-style prompts). No training is involved.
2. **Feedback source: external tools, with the LLM writing the critique.** QA critiques check "plausibility" and "truthfulness" against search evidence (top-1 page, at most 400 characters). Math uses interpreter errors and execution results. Toxicity uses the Perspective API score of the most toxic attribute (§4).
3. **Iterations.** QA: up to n = 3 corrections, stopping early if the answer is unchanged twice. Math: up to n = 4. Toxicity: up to 4 iterations, stopping when toxicity falls below 10%. "Typically, 2–3 rounds of corrections yield most of the benefits" (§4.4, Figs. 3–5).
4. **Main numbers.** With ChatGPT, CRITIC gives +7.7 F1 on average across three QA tasks, +7.0% on three math tasks and a 79.2% reduction in toxicity probability (§1). Table 1 (ChatGPT, F1): AmbigNQ goes from 64.3 with CoT to 74.9 with CRITIC (67.3 without the tool); HotpotQA from 42.8 to 52.9 (46.1 without the tool). Table 2: GSM8K goes from 72.5 with PoT to 78.2 with CRITIC (77.0 without the tool).
5. **The critical ablation: "CRITIC w/o Tool".** With the tools removed, the model's own critiques change QA F1 by −0.03 and +2.33 for the two LLMs (§4.1). On math they can hurt: text-davinci-003 GSM8K falls by 1.8 points below PoT (Table 2). The appendix (C.1, D.1) links this to LLMs being unable to tell "what they know": self-verification as hallucination detection is unreliable without tools.
6. **Oracle caveat.** CRITIC* corrects only the answers that are actually wrong and is reported as an *oracle* setting (e.g. ChatGPT AmbigNQ F1 79.9). These numbers are an upper bound, not a deployable result. CRITIC* beats best-of-N rejection sampling by 4.5 and 3.3 EM, which suggests that critiques add information beyond resampling (§4.4).
7. **Costs and limitations (App. A, D.3).** The time overhead grows linearly with the number of iterations; for math, two corrections take about twice the PoT baseline. Results depend on hand-written demonstrations, and the effect on other tasks and LLMs is untested. Search results were cached (about 9 GB) for reproducibility. The gains grow with model size (TabMWP +4.7 / +9.4 / +16.0 for LLaMA-2 7B / 13B / 70B, §4.2).

## Relevance to GroundOne
- **Strongest support for an external verifier in the loop.** CRITIC directly measures that the same loop with and without an external signal behaves very differently. That is the design argument for making [[GroundOne]] the feedback source in the demo instead of asking the generator to check itself ([[Verify-and-Revise Loops]]).
- **The difference is the kind of verifier.** In CRITIC the tool returns raw evidence and the *LLM* still writes the critique, so verification costs a generated rationale per round. In the demo, the verdict comes from a trained classifier reading the document already in context: one forward pass, a three-way label and a calibrated probability per sentence, with no generated tokens ([[Letter-Token Readout]], [[Calibration]]). The demo needs no tool call, because the evidence is the RAG context.
- **Being honest about "oracle" numbers.** CRITIC* (and Self-Refine's oracle appendix) assume a perfect detector. GroundOne is not one, so its false flags send correct sentences for rewriting and its misses let errors through. The dev-fitted threshold τ sets this trade-off explicitly, which no prompted critic in these papers does ([[Selective Prediction]]).
- **Iteration budget and latency.** CRITIC's linear overhead and the observation that 2–3 rounds capture most gains support a small default `max attempts`. Because GroundOne's verification is cheap (on the 16 GB M4, at K ≥ 14 sentences, about 0.41 s per answer for the 0.5B and 2.57 s for the 3B; see [[GroundOne Results]]), the generator's rewrite, not verification, dominates the cost of a round.
- **Gains scale with the generator.** CRITIC's improvements grow with LLaMA-2 size. A small local generator may repair less, so the demo should measure repair success directly.
