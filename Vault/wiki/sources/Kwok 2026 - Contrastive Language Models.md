# Kwok 2026 - Contrastive Language Models (CLM blog)

Raw file: `raw/Kwok 2026 - Contrastive Language Models (CLM blog)_ingested.md` (converted from the public Notion page; figures are only attachment ids, so plotted numbers are **not** available in the text).

## Overview
Notion blog post (posted 2026-09-23, **not peer-reviewed**, no arXiv paper) introducing [[CLM|Contrastive Language Models]], presented as "a new class of [[System One Models|System One model]]". A CLM is a **bi-encoder**: a state encoder and an action encoder, each a **frozen Qwen3-8B** backbone (last-token hidden state) plus a trainable MLP projection head (~20M parameters; 4096 → 1536 → 1536 → 512, GELU, LayerNorm). A state–action pair is scored by cosine similarity; a softmax over the candidate scores is the answer distribution. Trained with **bidirectional InfoNCE**, later with hard negatives. Released model: **CLM-8B**.

## Key Insights

### Method (as described)
- **Training recipe, three stages**: pre-training on ~60M Nemotron DQA question–answer pairs (question = state, answer = action); mid-training with ~30M synthetic hard negatives generated by Gemini 2.5 Flash-Lite; post-training on ~1M agent trajectories (Agent Data Protocol, Endless-Terminals, LiteCoder-Terminal-SFT) with 40% Nemotron replay.
- **Only the heads train**; LLM embeddings are precomputed once. A full pre-training run is said to take ~1 hour on one RTX 4090.
- **Disaggregated states and actions**: action embeddings are cached and reused; per step only the state is encoded (Super Mario: 5 forward passes → 1).

### Claims without numbers in the text
- "CLM-8B performs **on par with Jev**" on computer-use, gaming and tool calling (T-Rex, BFCL v4, WikiRacing, Super Mario) with "up to 9× lower latency" — the values are only in a figure. The repo's own T-Rex result files contradict "on par" on the decision-quality metric: choice agreement with the planner **0.658 (CLM) vs 0.987 (Jev)** (see [[CLM README]]).
- "Sets a new SOTA" on DeepSWE / Terminal-Bench 2.1: these are verifier best-of-N numbers on 38 and 30 tasks, after fine-tuning CLM; there is no confidence interval and the comparison against Jev uses Jev zero-shot.
- Speed comparisons against Jev mix a local GPU (4090/H100) with a remote hosted API including network round trip.

## Relevance to GroundOne
- **Related work only**: CLM requires vLLM/CUDA serving Qwen3-8B as a pooling encoder, which cannot run on the 16 GB M4 Mac, so it is not a runnable baseline.
- It defines the third family in the taxonomy of [[System One Models]]: **bi-encoder contrastive scoring**, as opposed to the LM-head letter readout used by GroundOne, [[SemIf]] and [[Rizzo-Flow]].
- Useful contrast for the thesis argument: CLM's speed comes from the state and the candidate never attending to each other (embeddings cached independently). For [[Groundedness Verification]] the "candidate" is a claim whose support depends on fine-grained token-level interaction with the context; a single pooled vector per side plausibly loses this (*inference, not tested by CLM or by us*). CLM's own mid-training gain (52.1% → 69.2% on hard negatives) shows fine-grained discrimination is exactly the hard part.
- The constrained-decoding baseline in the blog (single prefill + softmax over option labels on the same backbone) is essentially the GroundOne readout. The 97× gap there is driven by putting 1,024 candidates in the prompt, which does not occur in sentence-level verification (2 options per claim).
